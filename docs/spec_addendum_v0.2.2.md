# Specification Addendum v0.2.2

This addendum is a changelog for one clarification of `docs/formal_specification_v0.2.md`. The change below is present in that file (§3 Step 4, test cases NT22 to NT25 in §4.7, and the Resolved list in §7). The earlier addendum, `docs/spec_addendum_v0.2.1.md`, is unchanged and still describes the N16 correction. Its history is preserved: the first form of this clarification (NT22 and NT23 only, MATCH `Unknown` and DECL `Contradictory`) was extended in the audit pass described under "Revision" below.

## Unresolved-dimension ceiling (Step 4)

**Problem.** The §3 definition of Insufficient includes "a required dimension is missing or `Unknown`, or the evidence contradicts the claim or itself". Step 4 took only the minimum ceiling over triggered rules, and the rule tables of §4.2 do not name every state of every required dimension. When a Weak-ceiling rule triggered while a required dimension was in a state no rule governs, Step 4 gave Weak, although the same dimension state with no rule triggered gives the no-rule default Insufficient. For `Req(component_not_present)` the clearest case is MATCH `Unknown`, which §1 mandates whenever no target component is established.

**Change.**
- Step 4 now also applies an *unresolved-dimension ceiling*: a required dimension in a state that fails its Supported condition and that no rule in the predicate's table governs caps the verdict at **Insufficient**, even when every triggered rule has a Weak ceiling.
- States that a rule governs keep that rule's ceiling. For `Req(component_not_present)`: INV Unknown or missing (N2), INV Contradictory (N4), BIND Unknown or mismatched (N3), DECL Unknown (N5, N7), DECL Incomplete (N6), MATCH Present (N1), Ambiguous (N8), Incomplete (N9), Contradictory (N17), and for binary and container artifacts GEN `manifest_only` or `unknown` (N14, N15).
- The states that impose the ceiling are exactly: MATCH `Unknown`; INV `Absent`, `Incomplete`, `Ambiguous`; DECL `Absent`, `Ambiguous`, `Contradictory`.
- The ceiling is not a rule. No rule code is added, N1–N17 and their codes, classes and rationale ordering are unchanged, and no verdict category is added. Unresolved dimensions are reported in a separate `limitations` field as `<DIMENSION>=<State>`. The result holds one final verdict; there is no second, conflicting post-processing verdict.
- NT22 to NT25 are added. NT1–NT21 are unchanged; NT7, NT8 and NT11 remain Weak or Insufficient exactly as before, because DECL `Unknown` and GEN `unknown` are governed by N5/N7 and N15, which the specification states explicitly.

**Why governed states are excluded (not a blanket "any Unknown is Insufficient").** NT7, NT8, NT11, NT16 and NT17 are normative test cases that give Weak for DECL `Unknown` (N7) and for GEN `unknown` (N15). A blanket Insufficient ceiling for every `Unknown` dimension would contradict those cases and the rule table, so the ceiling is confined to states that no rule governs. This is a scope restriction that follows the specification's own explicit rules, not an implementation gap.

## Revision made in the audit pass

The first form of the clarification covered only MATCH `Unknown` and DECL `Contradictory`. A full-grid check of P-3 (monotone downgrade) over every state combination found 1140 input combinations in which **lowering** PROV_SBOM or PROV_DECL **raised** the verdict: with INV `Absent`/`Incomplete`/`Ambiguous` or DECL `Absent`/`Ambiguous` and everything else at P3 no rule triggers and the no-rule default gives Insufficient, while at P2 rule N12 (Weak) triggers and the literal Step 4 gave Weak. P-3 states that no rule may raise a verdict and that limitations can only lower one. The clarification was therefore extended to every state that fails a Supported condition and that no rule governs. This is the conservative reading and follows directly from P-3: it can only lower a verdict, only in states that already give Insufficient when no rule triggers, it leaves every governed rule outcome unchanged (NT1–NT21 are untouched, and for inputs with no ungoverned state the result equals the literal Step 4), and it adds no rule. It is recorded in the issue register as resolved for `Req(component_not_present)`; the reachability predicate remains open.

**Tests (`tests/test_cnp_rules.py`).** `test_every_required_dimension_state_is_either_ok_governed_or_capped` (table-driven over every dimension state and four Weak-trigger situations), `test_governed_states_keep_the_ceiling_the_specification_table_gives_them`, `test_a_governed_weak_state_together_with_an_ungoverned_state_is_insufficient`, `test_container_gen_weak_rules_do_not_hide_an_ungoverned_state`, `test_a_strictly_insufficient_rule_with_an_ungoverned_state_reports_both`, `test_p3_monotone_downgrade_lower_provenance_never_improves_the_verdict` (whole grid), the whole-grid invariant tests, and the explicit NT22 to NT25 cases, and the whole-grid check that the result equals the literal Step 4 wherever no ungoverned state is present.

**Effect on the reachability predicate.** None yet: the clarification is stated generally in Step 4, but §5 is not implemented and its governed states have not been enumerated.
